# 让你的 AI 协助使用或继续开发 Strata N1X

[返回首页](../README.md) · [安装说明](INSTALL.md) · [DSH 接入](DSH.md) · [开发说明](DEVELOPMENT-NOTES.md) · [源码构建](BUILD.md)

如果你已有可用的模型 API，或已经运行的本地模型，可以把下面的提示词交给自己的 AI 客户端，帮助理解环境、整理已有配置，或在明确任务范围后继续开发。

**能否实际操作电脑，取决于客户端的文件与命令工具、权限和当前连接状态。**普通聊天窗口可以解释和生成命令；只有获得相应工具及授权的客户端，才能读取本地仓库、编辑文件或执行命令。模型服务本身不会因为接通 API 就自动获得电脑控制权。具体客户端能使用哪些模型提供方，以该客户端实际支持范围为准。

下面三段是**根据本项目公开资料重新整理的可复用提示词**，不是原始 Codex 开发对话，也不是已经执行过的新案例。它们不能代替模型判断、设备兼容性或实际结果核对。

> 使用方法：选择一段，补充方括号中的任务信息，发给你自己的 AI。阅读或整理本文件不代表授权执行其中的任务；尤其第三段“继续开发”仅在你另行提出开发任务时使用。

## 选择入口

| 你的情况 | 使用哪一段 | 预期得到什么 |
|---|---|---|
| 不确定自己的电脑是否适合 | 提示词一 | 基于已有资料与本机信息的匹配表，列清已知与未知 |
| 已安装或正在按现有文档安装，DSH 配置遇到问题 | 提示词二 | 对当前路径的定位、最小改动和具体下一步 |
| 想在本项目上增加能力或修复代码 | 提示词三 | 有明确边界的开发方案；获得开发授权后落实到独立分支 |

本项目已有的公开记录覆盖维护者设备上的本地模型回复、桌面加载／卸载、DSH 基础两轮聊天和缓存复用。**这些记录不能自动证明某个 AI 客户端已经完成文件操作、工具调用、长时间 Agent 任务或完整 1M 输入。**详见 [DSH](DSH.md) 与 [已有观测](BENCHMARKS.md)。

## 提示词一：只读检查环境是否匹配

```text
请协助我判断这台设备能否使用 Strata N1X。

项目：https://github.com/zackyangzeqi-spec/strata-n1x-Zackyzq
本地仓库位置：[填写路径；没有本地仓库就写“只有项目链接”]
我的设备与目标：[填写已知设备信息、想用的模型和客户端；不知道的保留未知]

本轮只做读取、解释和匹配判断，不安装软件、不下载模型、不启动推理、不改配置。

请按以下顺序工作：
1. 先说明你当前能读取哪些资料、是否具备本地文件和命令工具。只有链接或普通聊天能力时，使用可访问的公开资料，不声称已经检查过我的电脑。
2. 读取项目 README.md、docs/INSTALL.md、docs/DSH.md、docs/FAQ.md、docs/BENCHMARKS.md；只有需要解释源码构建时再读 docs/BUILD.md。若项目还有适用于当前目录的 AGENTS.md，按其范围处理。
3. 有本机读取能力时，只查询判断兼容性所需的字段：系统及处理器架构、GPU 型号、驱动、物理内存、当前 GPU／RAM 分配、目标磁盘可用空间、相关应用版本。不要整份读取或输出账号凭据、环境变量、个人会话记录。
4. 分开判断：N1X 平台是否匹配、Windows ARM64 是否匹配、模型量化与文件布局是否已有记录、现有客户端是否能连接 OpenAI 兼容接口。不要仅凭“128GB 内存”判断可用，也不要把统一内存各统计口径直接相加。
5. 区分三件事：公开代码存在相应实现、维护者曾在其设备上运行、本机已经实际通过。只读检查通常只能支持前两项及本机环境匹配，不能写成本机实测通过。
6. 以“项目要求／本机或已提供信息／匹配情况／证据／下一步”的表格交付结果。事实标 [FACT]，根据资料推断标 [INFERENCE]，缺失信息标 [UNKNOWN]。

已经能完成的读取直接做，不要反复询问同一权限。只有缺失信息会实质改变结论时才集中提问；未获知的硬件或版本不猜测。

最后给我最短可行路径，并把普通安装包使用与源码编译分开。列出的任何后续安装或运行步骤都只是建议，不在本轮执行。
```

## 提示词二：协助已有安装与 DSH 配置排查

```text
请依据 Strata N1X 的现有文档，协助完成我这一次安装或排查任务。

项目：https://github.com/zackyangzeqi-spec/strata-n1x-Zackyzq
本地仓库位置：[填写；没有则说明]
我本次要解决的问题：[例如“已有 Strata 可以聊天，但 DSH 无法连接”；写入实际现象和报错]
我已授权的执行范围：[填写本次允许的操作；如果尚未授权修改，先只读定位并给具体方案]
已有资料：[安装包版本、DSH 版本、相关日志片段或截图；没有就保留未知]

先读取 README.md、docs/INSTALL.md、docs/DSH.md、docs/FAQ.md。使用当前文档中已有的路线，不主动替换推理框架、不增加新案例、不开展 benchmark 或全量长上下文实验。

按问题所在层次排查：
1. 设备和版本：确认是项目有记录的环境，分清公开安装包、源码工作树和正在运行的程序。
2. 模型准备：先辨认实际量化、模型目录、配套文件和已保存配置。不要因一个字段不一致就重新下载全部权重或删除缓存。
3. Strata：优先查看现有状态与日志，确认是否已有模型实例、是否就绪、实际服务地址是什么。不要额外启动第二个大模型实例，也不要把模型加载按钮等同于已成功回复。
4. API：本项目文档给出的桌面默认地址是 http://127.0.0.1:47831/v1，但以当前实例为准；不要误用内部动态引擎端口或公开补丁中的其他历史服务端口。若服务已经运行且读取被授权，可查询模型列表取得真实 Model ID；无需为了获取列表启动新推理。
5. DSH：核对提供方类型、Base URL、真实 Model ID、当前会话实际选中的提供方、上下文与输出预算、超时设置。模型 ID 不凭名称猜测。聊天提供方、嵌入模型、记忆和工具服务分别确认，不自动修改其他供应商配置。
6. 等待问题：区分处理输入、推理／生成、客户端等待和底层连接超时。历史开发机曾使用未随包发布的回环传输扩展；不能仅设置一个大超时数就承诺任意 DSH 版本有相同行为。资料不足时明确缺哪项，不凭空生成并安装所谓官方修复插件。

处理原则：
- 已经授权且为完成这次任务所需的可逆操作直接推进，不逐步重复请求确认。超出授权的新开发、删除数据、系统级改动、大量重新下载或向外发布，先提出具体方案再处理。
- 配置修改先保留可恢复副本，只改本次相关字段，不把全套个人配置或密钥输出到聊天、Issue 或 Git。
- 保持回环服务地址；不为排查而打开公网端口。可访问云端的搜索、插件和其他模型路由要与本地推理分别说明。
- 如本轮只获准文档整理或只读排查，不执行模型请求、重启、下载、编译或任何运行测试。
- 如本轮已经授权完成安装／连接，必要核对仅限这一目标和文档已有路径，说明实际做了什么、得到什么结果。无法执行时给“命令做什么／成功标志／如何取消／下一步”，不要声称完成。
- 遇到同一错误重复出现，收集关键证据后改变判断或汇报阻塞，不无限重试。

最终输出：已确认原因与证据、实际改动、剩余未知、可恢复方式、下一步。保持“记录表明”和“本次实际执行”分开，不能把维护者历史结果写成我的设备已经通过。
```

## 提示词三：在另行授权后继续开发

**这是未来开发任务的入口。文档更新、复制文件或阅读此页不会启动开发。**有可用 API 或本地模型之后，还需要合适的客户端工具、工作目录权限和明确的任务范围。

```text
请基于 Strata N1X 继续处理下面这个开发任务。

项目：https://github.com/zackyangzeqi-spec/strata-n1x-Zackyzq
本地仓库位置：[填写]
具体问题或新增目标：[填写；不要只写“全面优化”]
希望得到的可交付结果：[文件、功能或行为，以及完成标准]
本轮已授权范围：[“只读分析并给方案”，或明确填写已批准开发的范围]
不能改变的内容：[填写已正常使用的功能、版本、数据或接口约束]

请先建立事实基线：
1. 读取适用的 AGENTS.md、README.md、docs/BUILD.md、docs/DEVELOPMENT-NOTES.md，以及与当前任务有关的现有文件。检查 Git 分支、工作区差异和远端，保留已有未提交内容。
2. 这个公开项目提供针对固定上游基线的适配补丁。区分“公开补丁发布仓库”和“已经还原的完整 Strata 源码树”，不要假定补丁里出现的路径都已独立存在，也不要直接在未知上游版本上套用补丁。
3. 说明哪些内容已由公开代码证实、哪些来自已有测试记录、哪些只是推断。优先复用项目已有实现及有明确来源的成熟组件；如需要评估新依赖，解释具体收益、版本、维护情况和新增影响，不为完成任务任意替换技术栈。
4. 结合已经可见的会话、项目记录和 Git 历史还原相关决策。只有客户端确实提供相关历史记录访问能力时才读取与该项目匹配的材料，不声称自动知道另一台电脑的 Codex 会话。没有证据的历史动机标 [UNKNOWN] 或 [INFERENCE]。

如果当前仅授权方案：先交付问题定位、拟修改文件、预期行为、影响范围、最小验证与回退方式；不要直接开发。
如果当前已经批准这一具体开发范围：完成上述读取后直接推进，不再重复询问同一授权。

实施要求：
- 在独立工作分支或隔离工作树中修改，不长期在 main 开发；不覆盖无关改动、不强推、不自动合并或发布。
- 修改范围以本任务为限。保持上游归属、许可证、社区构建身份、运行数据与发布资产边界，不把社区哈希清单当成官方签名。
- 先解决能够证明的具体问题；不要顺手增加 benchmark、新演示任务、模型下载或大范围重构。运行验证仅在本次开发授权内、为该改动必要时进行，并如实说明未验证部分。
- 不能运行的项目只给静态判断，不把源码阅读写成运行通过；没有真实输出，不填写性能或功能验收成功。
- 当前可访问的 API 或本地模型不保证完成所有任务。能力或工具不足时指出具体阻塞，保留已有产物，不伪造工具结果。
- 如需要公开开发记录，仅整理脱敏的“问题→实现→理由及证据→已有结果→边界”；原始会话、认证文件、个人日志和无关项目资料不进入 Git。

交付时列出文件差异、行为变化、已做的必要核对、未做项和恢复办法。遵守项目既有审查流程；没有其他约定时以 READY_FOR_SUPERVISOR_REVIEW 交付，由 Owner 或指定审查者判断是否 PASS。不得自行宣布已通过用户验收。
```

## 如何留下值得复用的开发记录

让 AI 输出短而具体的决定记录，比把所有对话都放进仓库更有用。可以按 [开发说明](DEVELOPMENT-NOTES.md) 的格式，记录一个问题、对应文件或提交、已知结果和限制。若后来获得确切的本地原始提示词，可以在脱敏后另行注明“历史提示词摘录”；不要把本页重新整理的提示词倒写成历史事实。

API 模型与本地模型都能用于阅读这些提示词，但实际效果取决于模型、上下文、工具支持和任务难度。它们是协作入口，不构成安装成功、开发成功或性能的承诺。
