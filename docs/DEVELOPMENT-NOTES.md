## 1. 针对 Windows ARM64 的构建调整

**问题。**[FACT] 公开补丁对原先只判断 `_MSC_VER` 的若干代码增加了 x86／x64 条件，并为 Windows ARM64 的等待指令增加独立分支。补丁注释还记录了 clang-cl 19 ARM64 在部分编译单元 `/O2` 下的 SEH 汇编标签问题。

**实现。**`src/dsv41/ds4_gg_cpu.cpp` 与 `src/kernels/cpu/expert_layout.cpp` 将 x86 内建函数相关分支限制到对应架构；`src/dsv41/ds4_pool.hpp` 为 ARM64 使用 `__yield()`。`CMakeLists.txt` 新增默认关闭的 `STRATA_WINDOWS_ARM64_CLANG19_SEH_WORKAROUND`，只有在匹配的 Windows ARM64／clang-cl 19 条件下才允许开启，并将 `/O1` 限定到列出的三个编译单元。补丁也为 `strata-dsv41` 加入 UTF-8 manifest，桌面启动 Control 时设置 Python UTF-8 环境。

**理由与证据。**[FACT] 架构条件、开关及限制都直接写在 [补丁](../patches/n1x-windows-arm64.patch) 中；[BUILD](BUILD.md) 给出对应构建选项。[INFERENCE] 这类限制的作用是缩小兼容调整的影响范围，不能据此推导所有编译器、所有模块或其他 GPU 已经兼容。

**已有结果与边界。**[README](../README.md) 记录了维护者设备上的原生 CUDA 推理及桌面运行；[BUILD](BUILD.md) 同时保留独立干净环境完整构建尚需验证的边界。本文不提供新构建结果，也不把某个编译开关宣传为性能提升。

## 2. 让桌面识别对应的本机原生引擎

**问题。**[FACT] 补丁新增 `apps/host/server/n1x-native-engine.mjs`，专门处理 Windows ARM64 的 `deepseek41` 本机引擎。文件注释明确区分本机源码构建与通用或签名发布包。

**实现。**该模块检查 Windows ARM64 宿主；当 Node 进程本身处于 x64 仿真时，进一步查询宿主处理器架构。它读取本机或随包清单，核对清单种类、平台、模型架构与成员文件 SHA256，再检查可执行文件的 ARM64 PE 标识。模型配置中的可执行文件路径也必须匹配已识别引擎。桌面控制通过该模块获得可用性和说明信息。[清单工具](../tools/make_native_manifest.py) 用于为已有二进制生成相应记录。

**理由与证据。**[FACT] 检查顺序与配置绑定可直接从 [补丁](../patches/n1x-windows-arm64.patch) 核对。[INFERENCE] 这帮助桌面区别“找到一个文件”和“找到符合本适配声明的引擎”；它不证明文件由官方签发，也不等价于完整安全审计。

**已有结果与边界。**当前公开说明支持维护者设备上的加载与卸载。该识别逻辑聚焦 DeepSeek，不应据此声称所有模型家族已获得 N1X 原生适配。清单可能包含目标机器路径，构建说明要求留在对应机器，不公开私人运行配置。

## 3. 把 N1X 的资源策略与模型参数纳入已有流程

**问题。**[FACT] `setup.py` 的补丁注释说明，N1X 在硬件查询中还可能出现没有 CUDA compute capability 的 NPU 条目；该条目不应作为另一块 CUDA GPU 计算。另一处注释记录通用长上下文估算与 N1X 统一内存专家预算之间的适配问题。

**实现。**补丁过滤不具有数字 compute capability 的条目；仅在 Windows 且设备名称匹配 N1X 时加入相应准备策略，包括 `DS4_COPY_GB=0`、`DS4_UMA_GPU_RESERVE_GB=8`，以及专家、线程、预留、缓存和分块参数。`--ssd-cache` 在这里指系统 RAM 专家缓存预算，不是 SSD 容量；[BUILD](BUILD.md) 明确解释了这一点。`n1x-model-settings.mjs` 则只处理 DeepSeek 对应的上下文与 DSpark 参数，并检查输入范围。

**理由与证据。**[FACT] 上述条件和字段均见 [补丁](../patches/n1x-windows-arm64.patch)。[INFERENCE] 将平台策略限定在明确条件下，有利于避免把 N1X 参数直接套给其他设备。它不证明这些参数对所有 N1X 分配比例或所有工作负载都最优。

**已有结果与边界。**公开记录列出了维护者使用过的内存分配与配置；[已有观测](BENCHMARKS.md) 才是具体结果的来源。GPU／RAM 分配本身属于 NVIDIA 提供的硬件／驱动能力，本项目接入并展示相关状态。128GB 是共享总容量；1,048,576-token 配置不等于已完成完整 1M 输入验证。

## 4. 将原生引擎接入桌面模型管理与可读监控

**问题。**[FACT] 补丁修改 `native-control.mjs`、`NativeModels.tsx`、`VersionPicker.tsx` 与监控界面，并新增 `N1xRuntimeCard.tsx`。这些改动围绕已有模型的状态、加载、参数和资源显示展开。

**实现。**桌面可识别 N1X 原生引擎能力，沿用已准备模型配置启动对应实例，在健康检查后更新就绪状态，并接入卸载流程。N1X 模型页显示固定的 1024K 上下文与 DSpark 自动策略，保留实际运行参数说明；资源卡明确区分整机实测、最近检测和模型是否已加载。代码还提示统计包含系统及其他应用占用，不能将其称为模型独占占用。

**理由与证据。**[FACT] 状态与界面说明写在 [补丁](../patches/n1x-windows-arm64.patch) 中，公开 [README](../README.md) 和 [BENCHMARKS](BENCHMARKS.md) 提供对应桌面截图。[INFERENCE] 这些改动降低了“引擎在命令行可启动”和“日常桌面使用可理解”之间的信息断点；不能由界面出现按钮推断每个分支都已验收。

**已有结果与边界。**维护者已公开桌面模型加载／卸载与请求观测。资源图是观测工具，不是精度评估或并发能力保证；界面显示的模型回答也不能作为功能验收证据。公开资料仍将完整长输入、其他设备和长时间任务单独列为未充分验证范围。

## 5. 给社区适配版本独立的应用身份和更新边界

**问题。**[FACT] 公开包的应用名为 `strata_Zackyzq`，定位是社区预览。补丁中的 Tauri 配置、启动策略和 updater 处理了与这一身份相关的设置。

**实现。**Tauri 应用 ID 改为 `community.strata.Zack_yzq.n1x`，默认使用独立的 `.strata_Zackyzq` 数据根目录，并支持 `STRATA_ZACK_DATA_ROOT` 覆盖；桌面启动的子进程接收相应目录配置。更新端点清空，updater 对该社区应用身份返回需要手动安装已审阅版本的说明。源码中的目录设置作用于应用启动流程，不代表修改整台电脑的全局环境设置。

**理由与证据。**[FACT] updater 的代码注释明确说明社区构建没有已验证的更新源；对应实现见 [补丁](../patches/n1x-windows-arm64.patch)。[INFERENCE] 独立身份与数据目录有助于区分社区版和上游版的文件及运行状态，但不是独立账户安装已经通过的证明。

**已有结果与边界。**已有社区预览安装包；[发布范围](RELEASE-CHECKLIST.md) 保留未签名、独立干净账户与干净源码构建的验证边界。上游 Strata、Project Maya、ggml 及其他依赖仍保留各自归属和许可，见 [LICENSE](../LICENSE)、[ASSETS](ASSETS.md) 和相关第三方说明。

## 6. 通过本机 API 向 DeepSeek Harness 提供模型服务

**问题。**[FACT] [DSH 指南](DSH.md) 将 Strata 定位为模型生命周期与推理服务的提供方，DSH 使用本机 OpenAI 兼容 API 发送请求。二者的配置和能力验收需要分开。

**实现与已有结果。**公开指南给出的桌面默认 Base URL 为 `http://127.0.0.1:47831/v1`，实际使用应以运行实例及其模型列表为准。[历史 DSH 文档](https://github.com/zackyangzeqi-spec/strata-n1x-Zackyzq/blob/fef6e1f390074abf399230a445be325ae6eaaa05/docs/DSH.md) 记录了 2026-10-31 的两轮真实聊天：首轮约 30K 输入、DSH 耗时 227 秒、解码 8.8 tokens/s；追问耗时 19 秒、输入 30,102、复用 30,077、解码 10.1 tokens/s。这些是历史记录，不是本文新增测试，也不是每次请求的承诺。

**理由与证据。**[FACT] 历史文档同时说明该开发机使用了仅针对回环提供方的 DSH 传输扩展，以处理底层 HTTP 默认超时；扩展包含机器安装位置，没有随该包复制。因此不能只根据参数表宣称任意 DSH 版本均能获得同样等待能力。[INFERENCE] 通过稳定的本机服务入口连接客户端，可以复用已经运行的模型实例；这不意味着其他客户端功能已迁移。

**边界。**两轮聊天与缓存复用不覆盖工具执行、微信、嵌入／记忆、长期 Agent 任务或完整 1M 输入。DSH 的搜索、插件和其他提供方仍可能联网。补丁内还保留 `n1x-linux-attachment.mjs` 及使用其他服务端口的辅助路径；这些代码的存在不等于当前推荐的 Windows 原生路线依赖 WSL，也不能把内部 host agent 的改动当成外部 DSH 传输扩展已经公开随包分发。
